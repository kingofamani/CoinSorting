# 光耦測試程式（ESP32）— opto_test_esp32

搭配「光耦簡易測試原型」（一段滑坡＋一個槽型光耦模組）使用，驗證槽型光耦跨裝在滑坡上能不能可靠地數硬幣。
只接一路光耦，不需安裝任何函式庫。

## 接線

| 光耦模組 | 擴展板 | 說明 |
|---|---|---|
| OUT（有的寫 DO） | G27 那一排的 **S** | 4 腳模組的 AO 不接 |
| VCC | 同一排的 **V** | 黃色跳帽一定要設 **3.3V**，不可接 5V |
| GND | 同一排的 **G** | |

顯示器（可不接，接了會顯示目前枚數）：TM1637 CLK→G14、DIO→G13、VCC→V、GND→G。

## 燒錄

1. Arduino IDE 開啟 `opto_test_esp32/opto_test_esp32.ino`（資料夾名稱要和 .ino 同名）。
2. 開發板選「ESP32 Dev Module」；ESP32 core 2.0.x 或 3.x 都可以。上傳。
   - 下方訊息出現 `Connecting……` 時，**按住板子的 BOOT 鍵**，開始寫入（出現百分比）後再放開。這塊板子要手動按 BOOT；沒按會出現 `Failed to connect` 或 `Timed out`，再上傳一次並按住 BOOT 就好。
3. 序列埠監控視窗設 **115200**，換行設定選哪一種都可以。
4. 開好視窗後按板子的 EN（RST）鍵重開，才看得到開機的自動判定。**開機時槽裡不要放東西。**
5. 照開機訊息確認一次判定（見下面「輸出範例」的開機那段）。

編譯時如果出現 `section of 'onEdge' conflicts with previous declaration`：把 `void IRAM_ATTR onEdge()` 的 `IRAM_ATTR` 刪掉再編譯。功能不受影響。

## 指令（打完按 Enter）

| 指令 | 作用 |
|---|---|
| `c20` | 丟幣測試：接下來丟 20 枚（只打 `c`＝不指定枚數），丟完輸入 `e` |
| `e` | 結束丟幣測試，印出報告與建議值 |
| `k5` | 目前測的幣別：`k1`、`k5`、`k10`、`k50`（`k0` 取消），用來估算速度 |
| `b2.5` | 光束離軌道的高度（mm，預設 2.5），請照原型實際量的值改 |
| `v` | 每 50 ms 印出目前電位：開／關 |
| `p` | 逐筆印出每一個原始脈衝：開／關（看抖動） |
| `h`／`l` | 強制設定：擋住時輸出 HIGH／LOW |
| `a` | 重新自動判定擋住電位（槽裡先清空） |
| `g3` | 即時計數：光束連續亮 3 ms 以上，下一次擋住才算新的一枚（預設 3） |
| `d0` | 即時計數：從擋住開始算，幾 ms 內再擋住都算同一枚（前緣 DEBOUNCE，預設 0） |
| `r` | 歸零 |
| `?` | 說明與目前設定 |

- `g`、`d` 是「即時計數」（顯示器、`#N` 那幾行、報告「★ 結論」第一行）用的設定。報告裡的兩種方法會另外把所有候選值都試算一遍，不受 `g`、`d` 影響。
- **每次 `e` 印完報告，程式會把即時計數自動改成報告建議的亮區值、前緣歸零**（印出「本工具的即時計數已改用…」）。要讓每一輪的即時計數用同一個設定，就在每一輪 `c` 之前輸入 `g3` 和 `d0`。

## 測試步驟

正式的測試步驟（T1～T7）、過關標準和紀錄表在 `../組裝與測試說明.md` 第 7 節，請照那裡做；那裡的放幣線、幣別、光束高都已經配好，數據才能回填 v2。

只想先確認接線和程式的話：
1. 照開機訊息用紙片擋一次，確認判定沒有反。
2. 輸入 `v`：空槽時一直是「· 沒擋」、不出現「變化」；用紙片慢慢擋，「■ 擋住／· 沒擋」要乾淨地切換。再輸入 `v` 關掉。

報告的兩種計數方法：

- **方法一：前緣 DEBOUNCE**：舊程式的做法，從一枚開始擋住算起，這段時間內再擋住都算同一枚。
- **方法二：亮區重新上膛**：光束要連續亮超過一段時間，下一次擋住才算新的一枚。設計規格 R6 建議用這種（連續亮約 3～5 ms 才重新上膛）。它的下限只看抖動的亮縫，不受遮光時間長短影響。

## 輸出範例（示意，數字是編的）

開機：

```
光耦簡易測試原型：1 路槽型光耦（OUT→G27 的 S、VCC→V〔跳帽 3.3V〕、GND→G）
顯示器（CLK→G14、DIO→G13）：沒有回應（沒接也能用）

▶ 自動判定擋住電位（約 1 秒）：槽裡請不要放任何東西……
  閒置（沒擋）電位：LOW（1 秒內 HIGH 佔 0%、訊號變化 0 次）
  → 判定：擋住時輸出 HIGH
  如果剛才這 1 秒槽裡不是空的，判定一定是反的 → 清空後輸入 a。
  確認方法：用紙片擋住光束約 1 秒再拿開。
    正確：擋住的當下印「▼ 擋住（#1 開始）」，拿開後才印「#1 遮光 約 1000 ms」（遮光≈你擋住的時間）。
    判定反了：拿開時才印「▼ 擋住」，或擋住的當下就印出「#1 遮光…」→ 輸入 h 或 l 改過來。
  也可以輸入 v：槽空著要顯示「· 沒擋」，擋住要顯示「■ 擋住」。
```

接著照上面的方法用紙片擋約 1 秒再拿開，判定正確時會看到：

```
  ▼ 擋住（#1 開始）               ← 擋住的當下
  #1  遮光 1012.4 ms  （第一枚）   ← 拿開後約 3 ms
```

不在丟幣測試（`c`）時，每一枚都會先印 `▼` 那一行；丟幣測試中不印 `▼`，只在每一枚結束後印 `#N/20` 那一行。

`v` 模式（`*`＝這 50 ms 內擋過但已通過）：

```
    12.35 s  G27=0  · 沒擋    計數 0
    12.40 s  G27=1  ■ 擋住    計數 1
    12.45 s  G27=0  · 沒擋 *  計數 1  變化 2 次
```

每一枚（括號＝兩枚之間亮了多久）：

```
  #1/20  遮光   31.2 ms  （第一枚）  速度≈0.45 m/s
  #2/20  遮光   29.8 ms  間隔   812.4 ms（亮   781.2 ms）  速度≈0.47 m/s
  #3/20  遮光   33.0 ms  間隔   640.1 ms（亮   610.3 ms）  速度≈0.42 m/s  ⚠抖動：2 個脈衝
```

報告（節錄）：

## 常見狀況

- **開機說「閒置時訊號不穩」**：槽裡有東西、杜邦線鬆、VCC 沒接、跳帽不在 3.3V、強光直射，或模組壞了。排除後輸入 `a`。
- **開機說「G27 好像沒接到東西」**：OUT 沒插好。模組本身沒有上拉電阻時也會這樣；程式有開內建上拉，仍然可以用。
- **判定反了**，會有下面任何一種現象，輸入 `h` 或 `l` 改過來（或清空槽後輸入 `a`）：
  - 顯示器或 `v` 的計數在**拿開**時才 +1；`v` 在槽空著時顯示「■ 擋住」。
  - 序列埠在拿開時才印「▼ 擋住」，或在**擋住的當下**就印出「#N 遮光…」（這時的遮光時間其實是光束亮著的時間）。

  注意：「#N 遮光…」那一行本來就是拿開、光束重新亮了以後才印，這是正常的，不是判定反了。
- **「⚠ 光束已經連續擋住 3 秒」**：槽裡有東西卡住（卡幣），或開機那 1 秒槽裡有東西、判定反了。輸入 `v` 看：槽空著卻顯示「■ 擋住」就是判定反了，清空後輸入 `a`。用名片量光束高、手指擋著超過 3 秒時也會出現，那是正常的。
- **報告說「只收到 N 個脈衝，比預期少」**：有硬幣沒擋到光束。檢查光束高度、硬幣有沒有貼著軌道滾、模組有沒有裝正。
- **出現「漏記」**：訊號在很快地抖動，通常是接觸不良或電壓不穩。
